# HK Mixed Keyboard — Corpus

This directory contains the linguistic data that drives the keyboard's Chinese decoding layer.

## Structure

```
corpus/
├── tools/
│   ├── build_english_assist_corpus.py # Deterministic English→Chinese converter
│   ├── build_pinyin_corpus.py        # Deterministic offline CC-CEDICT converter
│   ├── build_t2s_map.py              # Deterministic OpenCC T2S converter
│   └── verify_corpus_manifest.py     # Shipped-asset integrity/provenance gate
├── sources/
│   ├── corpus_license_register.csv   # License & provenance record for every source
│   ├── corpus_manifest.json           # Hash, byte, row, license, and source lock
│   └── upstream/                     # Pinned upstream source snapshots
├── internal_stage1/
│   ├── hk_core_chars.csv             # ~60 HK Cantonese core characters
│   ├── hk_core_phrases.csv           # ~65 common HK phrases
│   ├── english_assist.csv             # Reviewed HK English→Chinese layer
│   ├── mixed_phrases.csv             # ~60 Chinese–English mixed collocations
│   └── whitelist_en.csv             # ~35 English words that must never become Chinese
└── README.md                         # This file
```

## File Formats

### hk_core_chars.csv

| Column | Type | Description |
|--------|------|-------------|
| `char` | string | The Chinese character |
| `quick_code` | 2-letter | First + last Cangjie radical key (Quick/速成 code) |
| `cangjie_code` | 2–5 letter | Full Cangjie radical sequence |
| `freq` | float [0–1] | HK-chat-weighted frequency |
| `hk_core` | 0 or 1 | 1 = HK-specific character not found in standard Mandarin input |

Characters with `hk_core=1` are highlighted blue in the candidate bar and receive tieBreak preference when the buffer length ≤ 2.

### hk_core_phrases.csv

| Column | Type | Description |
|--------|------|-------------|
| `phrase` | string | Multi-character phrase |
| `quick_code` | string | Concatenated Quick codes of constituent characters |
| `freq` | float [0–1] | HK-chat-weighted phrase frequency |
| `hk_core` | 0 or 1 | 1 = HK-specific collocation |

Phrases rank above single characters in the candidate bar when the Quick code matches exactly.

### mixed_phrases.csv

| Column | Type | Description |
|--------|------|-------------|
| `trigger_en` | string | The English word that triggers this suggestion (e.g. `send`) |
| `phrase` | string | The mixed Chinese–English phrase shown as a completion (e.g. `send返`) |
| `freq` | float [0–1] | Estimated HK-chat frequency |

These appear only for an exact Quick composing trigger and are always tap-only;
Space and punctuation never auto-commit them. They are not offered from
Jyutping or Pinyin composition buffers.

### chinese_assist.csv

| Column | Type | Description |
|--------|------|-------------|
| `chinese` | string | Exact Traditional Chinese text committed by the user |
| `english` | string | Reviewed English assist label/output |
| `freq` | float [0–1] | Explicit reviewed ranking score |

This deliberately small, reviewed overlay is shown only after an exact Chinese
post-commit prefix and is visibly marked `中→英`. It is not generated by
reversing CC-CEDICT glosses; tapping it inserts the English text and ends the
Chinese next-character prediction chain.

### whitelist_en.csv

| Column | Type | Description |
|--------|------|-------------|
| `word` | string | English word that must always be committed as English |
| `canonical` | string | Canonical casing override (empty = use as-is). E.g. `mtr` → `MTR` |

Whitelist entries always win over any Chinese decode that shares the same Quick code (e.g. `ok` = 仗 is suppressed).

### pinyin.csv

`android/app/src/main/assets/corpus/pinyin.csv` is generated offline from the
pinned CC-CEDICT snapshot. Its fields are `pinyin`, `chinese` (the Traditional
headword), and `freq`. Keys are lowercase and toneless; whitespace,
apostrophes, hyphens, and other separators are removed, while `ü` and `u:`
become `v`; the resulting key contains only ASCII `a-z`.

An exact Traditional-text match in `hk_core_chars.csv` or
`hk_core_phrases.csv` supplies the frequency only when that row has
`hk_core=0`; Cantonese-specific `hk_core=1` rows never boost Pinyin candidates.
Unmatched entries use a fixed, deterministic length/type heuristic: `0.3000`
for a single character, `0.2500` for a two-character word, and `0.2000` for a
longer phrase. The canonical product example `mao` ranks `貓` first without
depending on file order: its persisted generated score is the documented
override `1.0000`, strictly above every competing `mao` candidate.

The generator validates the compressed source SHA-256 before reading it. It
requires and validates CC-CEDICT `entries`, `version`, `subversion`, `format`,
`charset`, and `date` metadata, accepts only the pinned `version=1`,
`subversion=0`, `format=ts`, `charset=UTF-8` format, rejects malformed records
and verifies the parsed count. Generation also fails if the corpus exceeds
130,000 rows, 4 MiB, 256 candidates for one key, or the 72-letter bounded
Pinyin composition ceiling.

After normalization, a canonical Mandarin syllable inventory must fully cover
the continuous key. This keeps valid spellings (including `lv`/`nve`,
`ju`/`qu`/`xu`/`yu`, erhua `r`, and rare `fiao`/`sei`/`tei`) while excluding
placeholder readings such as `xx` and acronym-only readings. The Android
decoder repeats this validation before building its runtime indexes.

Before toneless normalization, each raw reading is validated against the
pinned source syntax: ASCII-letter Pinyin or acronym tokens, tone digits
`1`–`5` only at token ends, `u:` notation, spaces, commas, and middle-dot
separators. Apostrophe and hyphen syllable separators accepted by the input
normalizer are also validated. Standalone numeric literal tokens present in
CC-CEDICT are allowed; mixed digit/letter tokens and unexpected characters are
rejected. Syntactically valid acronym readings may still be excluded by the
canonical Mandarin-syllable validation above.

Rebuild it without network access from the repository root:

```bash
python3 corpus/tools/build_pinyin_corpus.py \
  --cedict corpus/sources/upstream/cc-cedict-2026-07-12T162325Z.u8.gz \
  --source-url 'https://cc-cedict.org/editor/editor_export_cedict.php?c=gz' \
  --source-date '2026-07-12T16:23:25Z' \
  --source-sha256 '90e2881776366f606171a977a1f54786196f428ba604c728a279d4aaff7223a8'
```

Run the generator tests with
`python3 -m unittest discover -s corpus/tools/tests -v`.

### english_assist.csv

`android/app/src/main/assets/corpus/english_assist.csv` is generated from the
pinned CC-CEDICT Traditional headwords, a pinned 50k English frequency
vocabulary, and pinned `rime-essay` counts. Only ordinary frequency-vocabulary
gloss keys (plus safely bounded compound and apostrophe keys) are exposed. A
direct dictionary gloss ranks ahead of an incidental word in a long example;
RIME counts break ties. The separately pinned
`internal_stage1/english_assist.csv` rows remain higher-priority curated HK
entries, while `english_assist_overrides.csv` remains the visible HK product
layer.

Rebuild it offline from the repository root:

```bash
python3 corpus/tools/build_english_assist_corpus.py \
  --cedict corpus/sources/upstream/cc-cedict-2026-07-12T162325Z.u8.gz \
  --cedict-sha256 '90e2881776366f606171a977a1f54786196f428ba604c728a279d4aaff7223a8' \
  --frequency-words corpus/sources/upstream/frequencywords-en-50k-525f9b560de45753a5ea01069454e72e9aa541c6.txt \
  --frequency-words-sha256 '5351ff405b1126ef555791dd4d9798a48e3e9a501a9fc481a9da957752cfb458' \
  --essay-source corpus/sources/upstream/rime-essay-0debef3f5ae37f081758dd8bbd1fe79719410f7c.tar.gz \
  --essay-sha256 '4f32414039eb7f8a876acd8e94bd81c78fefafde56a352f7a3b8b2b74ca09c71' \
  --curated-sha256 'd435d36be9db41697c17d63cdd1d99f0129bc41d9cc013d7dd82f45a7cbb70bb' \
  --source-url 'https://cc-cedict.org/editor/editor_export_cedict.php?c=gz' \
  --source-date '2026-07-12T16:23:25Z'
```

### jyutping.csv

`android/app/src/main/assets/corpus/jyutping.csv` is generated offline from a
pinned `rime-cantonese` archive. The generator uses only explicit readings from
the character and word dictionaries plus the bundled `essay-cantonese`
frequency table. Words with frequency below 101 and phrase-table rows without
explicit readings are excluded; the ODbL-licensed maps table is not used.
Tone digits and spaces are removed, duplicate key/text pairs are merged, and
each key is capped at 256 candidates. Reviewed Hong Kong ranking corrections
remain isolated in `jyutping_overrides.csv`.

Rebuild it without network access from the repository root:

```bash
python3 corpus/tools/build_jyutping_corpus.py \
  --source corpus/sources/upstream/rime-cantonese-c99b16e44d2df77a5cb8fb0867dd2bab7a112cb0.tar.gz \
  --source-url 'https://codeload.github.com/rime/rime-cantonese/tar.gz/c99b16e44d2df77a5cb8fb0867dd2bab7a112cb0' \
  --source-commit 'c99b16e44d2df77a5cb8fb0867dd2bab7a112cb0' \
  --source-date '2026-07-02T11:05:50Z' \
  --source-sha256 '83fddd062104abac17fbc0c039f2c22c57671e96c5395a00abc326fd9ceeedfd'
```

### jyutping_tonal_readings.csv (preservation reference)

The shipped `jyutping.csv` is deliberately toneless so users type without tone
digits, which discards the 1-6 tone marks and multiple readings. To keep that
cultural-preservation record, `corpus/reference/jyutping_tonal_readings.csv`
exports every character with all of its explicit tonal readings (in source
order) and its Unicode code points, including supplementary-plane characters.
It is a versioned, checksummed **repository export — not bundled into the
APK** — so the tone data survives independently of the runtime decoder. Rebuild
it byte-for-byte from the same pinned `rime-cantonese` archive:

```bash
python3 corpus/tools/build_jyutping_tones.py \
  --source corpus/sources/upstream/rime-cantonese-c99b16e44d2df77a5cb8fb0867dd2bab7a112cb0.tar.gz \
  --source-url 'https://codeload.github.com/rime/rime-cantonese/tar.gz/c99b16e44d2df77a5cb8fb0867dd2bab7a112cb0' \
  --source-commit 'c99b16e44d2df77a5cb8fb0867dd2bab7a112cb0' \
```

### Quick assets

`hk_core_chars.csv` and `hk_core_phrases.csv` are generated from pinned
`rime-cangjie` and `rime-essay` archives. Canonical alphabetic Cangjie codes
are reduced to their first and last keys. Reviewed Stage1 HK rows are merged by
text and their codes are recomputed rather than trusted as source data.

Run `python3 corpus/tools/build_quick_corpus.py --help` for the fully pinned
offline rebuild command; all source and reviewed-input hashes are locked in
`sources/corpus_manifest.json`.

### hkscs_supplement.csv

`android/app/src/main/assets/corpus/hkscs_supplement.csv` is a deterministic
overlay containing every official HKSCS-2016 Han record. It is generated from
the pinned DATA.GOV.HK JSON snapshot: an official Cangjie code becomes the
first-and-last-key Quick code, and official Cantonese readings become toneless
Jyutping keys. The two records absent from both bundled input corpora and with
neither official field receive only a technical, tap-only Unicode escape
(`u200cd` and `u200d1`); no linguistic mapping is invented.

Source: <https://data.gov.hk/en-data/dataset/hk-dpo-dpo_hp-hong-kong-supplementary-character-set-related-information>

DATA.GOV.HK's terms require source acknowledgement. Any redistribution of this
derived overlay must acknowledge the Hong Kong Supplementary Character Set and
DATA.GOV.HK/OGCIO source. Regenerate and check it offline from the repository
root:

```bash
python3 corpus/tools/hkscs_coverage.py \
  --emit-supplement /tmp/hkscs_supplement.csv
cmp /tmp/hkscs_supplement.csv \
  android/app/src/main/assets/corpus/hkscs_supplement.csv
```

### t2s_map.tsv

`android/app/src/main/assets/t2s/t2s_map.tsv` is a deterministic export of
pinned OpenCC `TSCharacters.txt` and `TSPhrases.txt`. Phrase rows are retained
as greedy conversion overrides and each OpenCC value uses its documented first
target. This makes phrase-sensitive conversions such as `乾隆` reproducible
without changing the traditional internal dictionaries.

```bash
python3 corpus/tools/build_t2s_map.py \
  --source corpus/sources/upstream/opencc-ea6af199fefd6ab9b79015b5b93fef8b6b95c8b5.tar.gz \
  --source-sha256 '09ff1819bf8de167daeb1e0dfccb8ee1ec70f8ce7537f3c1abc3c5a7ba1a90dc'
```

## Shipped Asset Manifest

`sources/corpus_manifest.json` is the release inventory for every file under
`android/app/src/main/assets/corpus/` and
`android/app/src/main/assets/t2s/`. Each entry pins its SHA-256, byte size,
data-row count, license identifiers, provenance status, and the runtime corpus
content version. The verifier also fails when a shipped asset is added without
a manifest entry, and regenerates `hkscs_supplement.csv`, `english_assist.csv`
and `t2s_map.tsv` byte-for-byte from their pinned sources and declared inputs.

Run the integrity and provenance gate from the repository root:

```bash
python3 corpus/tools/verify_corpus_manifest.py
```

Provenance statuses are deliberately strict:

- `reproducible`: pinned input snapshot, checksum, source metadata, and a local
  deterministic generator are all present.
- `reviewed-curated`: project-maintained rows with an explicit review note.
- `legacy-snapshot-only`: the shipped output is hashed and licensed, but its
  exact upstream revision or generator was not retained. It must not be
  described as reproducible until those inputs are recovered and reviewed.

Quick, Pinyin, Jyutping, HKSCS, English-assist, and OpenCC T2S assets are now
reproducible. The Chinese-to-English assist is intentionally marked
reviewed-curated and limited in scope.

## Automated three-mode coverage evidence

`benchmarks/three_mode_source_coverage_cases.csv` is a deterministic 540-case
corpus-consistency fixture: 180 sampled keys each for Quick, Jyutping and
Pinyin. Regenerate it and run its asset-level ranking check with:

```bash
python3 corpus/tools/build_three_mode_coverage_cases.py
python3 corpus/tools/run_three_mode_coverage_benchmark.py
```

Every generated row is labelled `automated-source-derived`. The fixture proves
that current source-derived ordering remains internally consistent; it is not
a native-speaker linguistic-quality benchmark and must not be presented as
one. See `docs/cultural_preservation_release_gates.md` for the required human
review and device evidence.

## Corpus Design Principles

1. **HK-first**: Characters and phrases reflect Hong Kong Cantonese usage, not Mandarin written Chinese.
2. **Privacy-safe**: No user sentences, chat logs, or identifiable data are stored here. Corpus is derived from internal frequency estimation.
3. **Static at runtime**: The corpus is bundled as read-only assets. User personalisation lives in the Room database (`user_memory` and `custom_words` tables), not here.
4. **Quick code accuracy**: All Quick codes are verified against the standard 速成 (Quick) table — first character key + last character key of the full Cangjie sequence.

## Adding New Words

To add words to the bundled corpus, edit the CSV files under `internal_stage1/` and rebuild the app. For user-specific words, use the **管理自訂詞語** screen in Settings — those are stored in the on-device Room database and are not affected by app updates.
