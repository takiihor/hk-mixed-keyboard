    二、逐模式評分

  速成(Quick)—— B(可上架,有結構性缺口)

  - 字覆蓋充足:18,782 字全 Cangjie5,已做繁簡淨化(爲→為、簡體殘留移除)。
  - 缺口(結構性):9 個 Ext-B 港式俗字打唔到 —— 𠝹(𠝹開/lei6)、𡃁(𡃁妹)、𨋢(搭𨋢/lift)、𥄫(gap6 眼)等。原因是 Cangjie5 表本身無這些碼,非數據錯誤,但「100% 打得出所有廣東話字」在速成模式未達標。
  - 詞庫:50 個常見口語詞中 35 個(聽日、點解、食飯、睇戲…)無直接詞條;速成逐字上屏,影響較細。

  粵拼(Jyutping)—— 字覆蓋 A,排序 C(嚴重問題)

  - 字覆蓋是三模式最強、真正達到保育水平:幾乎所有 HKSCS/Ext-B 港式俗字齊全(𨋢 𠝹 𡃁 乸 孭 冚 嘥 嗌 掟 揈 嘜 嚿 罅 攞 嬲 焗 煲 曱 甴 全部有讀音)。只有 餸、脷 缺單字讀音(詞組 買餸 有)、兩個極罕 Ext-B 缺,基本可視為完整。
  - 🔴 一級缺陷 —— 頻率排序錯亂,把粗口推到第一:
    - 打 hai(粵語最高頻字「係」),候選第一是 閪(0.629) 這個粗口,排在 系(0.318)、係(0.300)之上;屄 亦在前列。一個做文化保育定位的鍵盤,最常用音節首選竟是粗口,這是質量與聲譽雙重風險。
    - 核心口語字全部被壓低:佢(keoi)排第 3、食(sik)排第 3、咁(gam)排第 5、噉 排第 23、嚟 排第 12–16。
    - 根因:freq 明顯來自書面 /essay 語料(偏文言、偏普通話),不是真正的廣東話口語頻率。
  - 🔴 二級缺陷 —— 最常用詞缺直接詞條:你好、唔該、聽日、點解、食飯、睇戲、唔使、琴日、而家 全部無直接詞條,只能靠連續拼音「合成」。
  - 🔴 三級缺陷 —— 連續合成因排序而出錯(實測):
    - sikfaan → 式飯(應為食飯)、tingjat → 聽一(應為聽日)、keoidei → 區地(應為佢哋)、haimai → 閪米(粗口)。
    - 合成邏輯本身正確(最大munch + 逐音節取頻率首位),但因為單字頻率錯,取到錯字。neihou→你好、mgoi→唔該、dimgaai→點解 只是「啱好頻率對」而僥倖正確。

  拼音(Pinyin)—— B(排序最健康,但最新、未經測試)
  
  - 排序正確:ni→你、hao→好、wo→我、de→的、shi→是、nihao→你好、xiexie→謝謝、weishenme→為什麼、zhongguo→中國 全部首選正確。這是三模式中頻率最可靠的。
  - 「缺 26 個廣東話字」是正常且正確的——那些是粵語專用字,普通話本無讀音,不算缺陷。
  - 輸出繁體(headword 為繁體),與全 App 定位一致。
  - 風險是成熟度:全新程式碼、3MB 字庫、零真機測試。程式已加降級保護(拼音字庫未載入 / 解碼失敗都會 graceful degrade 而非崩潰),工程上做得穩陣,但仍需上機驗證。

  三、中英雙向提示:優化空間很大

  打英文提示中文(English→Chinese)—— 有,但港式在地化差:
  - bus → 汽車 / 公車(港人講 巴士);taxi → 的 / 出租車(應為 的士)。用的是通用 CC-CEDICT 釋義,唔係香港詞。
  - ok 完全無結果;sorry → 愴(錯,應為對唔住/抱歉)。有明顯 CC-CEDICT 雜訊字。

  打中文提示英文(Chinese→English)—— 完全冇實作。 程式碼中無任何反查索引(byChinese / reverse index 皆不存在)。這正是你問的「優化空間」:此功能目前是零。對學習者 / 移民離散族群,「打中文睇返英文」是高價值且與離線定位相符的新功能。

  mixed_phrases.csv 只有 66 行,中英 code-switching 幾乎未開發。

  四、「字庫 100% 完整、做到文化保育水平」結論

  - 粵拼模式的字覆蓋已達保育水平——這是全 App 最有價值、最接近目標的部分,罕用港字齊全。
  - 但兩件事令它未達「保育級成品」:
    a. 頻率排序把粗口與文言字推前、核心口語字壓後 —— 保育的字有,但「用起上嚟」感覺劣質。
    b. 速成模式打唔到 Ext-B 俗字(𨋢/𠝹 等),所以「所有廣東話字都打得出」只在粵拼成立,速成不成立。
  - 一句話:你已經有保育級的「字」,但未有保育級的「頻率」與「詞」。 差距不在收字,而在權重與詞條。
